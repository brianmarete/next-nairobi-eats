# Nairobi Eats

Next.js site with [Payload CMS](https://payloadcms.com), Postgres, and Cloudflare R2 media storage.

## Local development

### 1. Postgres

Create the database (once):

```bash
createdb nairobi_eats
# or: psql -c "CREATE DATABASE nairobi_eats;"
```

If you use Homebrew Postgres, your connection string is usually:

```
postgres://YOUR_MAC_USERNAME@localhost:5432/nairobi_eats
```

Docker is optional — see `docker-compose.yml` if you prefer a container.

### 2. Environment

Copy `.env.example` to `.env.development` and fill in values (R2, Google Maps, etc.).

`DATABASE_URI` should point at your local Postgres instance (see above).

### 3. Install and run

```bash
npm install
npm run dev
```

On first run against a new database, Payload syncs the schema automatically when you start the dev server (`npm run dev`).

Open [http://localhost:3000](http://localhost:3000). Admin: [http://localhost:3000/admin](http://localhost:3000/admin).

## Deploy to Render (Postgres)

This repo includes a [Render Blueprint](https://render.com/docs/blueprint-spec) (`render.yaml`) that provisions:

- A **PostgreSQL** database (`nairobi-eats-db`)
- A **Web Service** (`nairobi-eats`) with `DATABASE_URL` wired automatically

### Steps

1. Push the repo to GitHub/GitLab.
2. In the [Render Dashboard](https://dashboard.render.com), click **New → Blueprint**.
3. Connect the repository and apply the blueprint.
4. Set the environment variables marked `sync: false` in `render.yaml`:
   - `NEXT_PUBLIC_SITE_URL` — your Render URL or custom domain (e.g. `https://nairobi-eats.onrender.com`)
   - `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`
   - `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` (optional)
5. Before the first deploy, generate migrations locally (see below) and commit them. The build runs `npm run migrate` to apply them to Render Postgres.

`PAYLOAD_SECRET` is generated by Render. `DATABASE_URL` comes from the linked database.

### After deploy

- Site: `https://<your-service>.onrender.com`
- Admin: `https://<your-service>.onrender.com/admin` — create your first user there.

### Migrations (optional, recommended later)

For the first Render deploy (and any schema change), create migrations from your machine while pointed at Postgres:

```bash
# Optional: use Render's *external* database URL for migrations that match production
# export DATABASE_URL="postgres://..."
npm run migrate:create
```

Commit the files under `src/migrations/`. Render's build already runs `npm run migrate`.

### Migrating from SQLite

Existing content in `payload.db` is not migrated automatically. Export/import via Payload or re-enter content after switching to Postgres.
